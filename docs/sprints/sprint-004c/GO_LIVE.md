## C. Technical follow-ups from the final review (before A3 runs; none blocks the pilot)

- **Artifacts:** `redact-results.ts` keeps `nonpilot-refusal.txt` verbatim and the quality report's `fatal` strings. Write a fixed classification line for the refusal and reduce `fatal` to counts, before any other file than the checksum-fixed X-Wines set goes through the workflow (LWIN, B4).
- **`merge_wines`:** scope the origin move to the merging household (`and household_id = hid`), as a safeguard, in a **new** migration. Not reachable through the API today: `record_wine_origin` requires the owning household.
- **`perf.ts`:** a single-round-trip transaction mode and server-side timing, for A3.
- Done in #115: an unreadable migration history on a hosted project fails the check; pilot transactions clear the claims.

## Technical verdict

- **GO** for the X-Wines integration as built: the pilot route on staging, the code in production with every source off, R-27, and the scan suggestions.
- **NO-GO for public or commercial activation** of X-Wines or LWIN until A1–A3 and A5 are done: the rights (A1–A2), the performance at 16 concurrent searches over a public source (A3), and a production import route (A5).
