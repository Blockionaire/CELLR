## Scope and files

- `apps/web/src/server/sommelier/intelligence.ts` — the orchestrator. One question: understand (dish, intent,
  budget) → gather (the household's cellar, its own wine profiles, the asker's taste) → assess every wine → decide
  → advise what to buy → ask at most one question back. No model in any step. Returns a plan.
- `packages/domain/src/sommelier-plan.ts` — the plan: outcome, picks with reasons and notes, the closest wine
  when nothing suits, wines set aside and why, styles to buy, verified offers, the question back, the state.
  Validated with zod wherever it is read back (`readPlan`, `isStoredAnswer`).
- `apps/web/src/server/sommelier/service.ts` — the V1 service gets an optional `intelligence`. Present: questions
  that name a dish or ask to buy go to the engines first; a question of fact goes to the counted facts as before;
  a general question goes to the model as before, with the model's own verdict dropped (and its buying advice
  dropped when the engines give buying advice). Absent: nothing changes.
- `packages/domain/src/features.ts` — four switches that `CELLR_FEATURES=all` does not turn on.
- `apps/web/src/features/sommelier/plan-view.tsx`, `sommelier-screen.tsx`, messages in English and Dutch.
- Registry: `svc-sommelier` names the engines and the four switches (version 1.2.0).
- Benchmark: `scripts/sommelier-eval/engines/v3-app.ts` (the app's own service with the engines on, conversations
  played turn by turn).

## What the inventory decides

| Situation                                       | What the plan does                                                    |
| ----------------------------------------------- | --------------------------------------------------------------------- |
| Every bottle of a wine is kept for an occasion  | not offered; listed as set aside, reason "reserved"                   |
| Some bottles kept, one free                     | offered, with the note "partly reserved"                              |
| Before its drinking window ("young")            | not offered; set aside, "too young"                                   |
| Still developing                                | offered, note "young"                                                 |
| Past its window                                 | offered, note "past"; when the window is only a guess: "may be past"  |
| Turned down earlier in the conversation         | not offered again; set aside, "turned down"                           |
| Wines the question names ("Chablis or Barolo…") | those are judged; the rest of the cellar only when none of them suits |
| Nothing suits                                   | outcome "none"; the closest wine is named as such, never offered      |

Evidence: a profile counts as fact about the exact wine only on the terms shared profiles are held to (researched,
`exact_wine`, high confidence, a source), and only when it states three of four scales. Every pick carries its tier;
the plan's confidence is the least of the dish's and the least-known pick's.

## Independent review (S3 and S4 together)

A separate reviewer attacked the branch. Verdict: **approve with changes; safe while off, not ready to turn on**.

| #    | Sev. | Finding                                                                                                                                | Disposition                                                                                                                        |
| ---- | ---- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| P1-1 | P1   | A colour word stuck for the whole conversation, and food words counted as one ("red cabbage"); the plan then said the cellar was empty | **Fixed.** A colour is a wish only when said as one; a new dish starts without it; the plan carries how many wines were considered |
| P1-2 | P1   | Wines named in the question were ignored when choosing                                                                                 | **Fixed.** Named wines the household owns are judged first; the rest only when none suits                                          |
| P1-3 | P1   | Ordinary questions got "What are you eating?" instead of an answer                                                                     | **Fixed.** Anything about wine, a cellar or a meal, and small talk, goes to the general sommelier as before                        |

| P1-5 | P1   | Money and intent misread ("max 2 flessen" as €2, "in what order" as buying)                                                            | **Fixed.** Numbers with a unit and bare years are not money; buy words narrowed; 20 sentences as tests                             |
| P2-1 | P2   | A kept plan was never validated; a link could be any URL                                                                               | **Fixed.** `isStoredAnswer` validates the plan; links are https by schema and by the screen                                        |
| P2-2 | P2   | Offer checks: any host allowed by default, ports, loose timestamps, stock not required for a store                                     | **Fixed.** No host list means nothing is shown; no ports; ISO timestamps with a zone; a store must confirm stock                   |

| P2-4 | P2   | Engine answers had no limit; the cellar was read twice                                                                                 | **Fixed.** Own rate limit (300 per hour); the cellar is passed on                                                                  |
| P2-5 | P2   | It asked where to buy and for the location with no retailer source to use the answers                                                  | **Fixed.** Not asked without a source. Three benchmark checks that expect those questions now fail by design                       |
| P2-6 | P2   | The model's buying advice was dropped also where the engines give none                                                                 | **Fixed.**                                                                                                                         |

Confirmed fine by the reviewer: every read is the household's own (row-level security); ids from the screen are only
ever a filter; a forged state does no harm; the switches stay off for unset, empty, `all` and garbage; without a
source no price, link, merchant or stock can appear; no XSS sink.

## Limitations

- **No end-to-end (browser) test covers the plan view.** The Playwright servers run with `CELLR_FEATURES=all`,
  which does not turn the sommelier on, and no run with the switch named was added. Open for S8 or the owner.
- The plan is worded by fixed sentences; no model wording exists yet (planned for S7, optional).
- Menus, wine-to-food, serving and quantities are not wired (S6).
- A cellar of 2,000 wines costs about 160 ms of CPU per question (measured by the reviewer).
