# Sommelier V1+ — P6: the `menu` part

2026-11-23, a branch from `main` at `b13cf26` (after P2, #123). Plan:
[`../SOMMELIER_CLOSEOUT.md`](../SOMMELIER_CLOSEOUT.md) §6 (P6). No paid model call, no migration, no switch on, no
production change. The part is off unless `CELLR_SOMMELIER` names `menu`.

## 1. What it does

V1's model keeps choosing the wines, in the one call it always made. The part gives it the structure of the question
and checks what comes back.

| Question                                              | What the model is given                                                       | What is shown                                                                                  |
| ----------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| A menu of several courses                             | The courses, numbered; the answer's schema extended with one entry per course | One row per course: the course in the person's words, its wine as a card, the reason in a line |
| A follow-up about that menu                           | The menu again, as context only; V1's own schema                              | V1's ordinary answer                                                                           |
| "The Tignanello or the Pavillon Rouge with the lamb?" | Both wines kept on the list, and the request to choose                        | Both wines as cards, the one the model would open first                                        |
| Anything else                                         | V1's message and schema, byte for byte                                        | V1's answer                                                                                    |

**Never more than one model call.** The schema, and the room for the answer (70 tokens per course, at most 600 more),
are extended only for a new menu.

**Everything per course is checked in code** (`checkMenuAnswer`): a ref that is not on the list the model was shown
gives that course no wine and no reason; entries are matched to courses by number, the first one wins, numbers out of
range are ignored; a reason with money or a shop in it is dropped; a wine poured with two courses is drawn once and
named again in words. A plan that comes back empty or broken is not shown as a menu: the answer is then V1's ordinary
one, never an error.

**Reused from #95:** `parseMenu` (eight courses at most), ported by hand with its tests. `said` is now the course in
the person's own words rather than the raw piece of text. Not taken: `planMenu` and the engines' orchestration (the
model chooses, not the engine), `asksWhichOf` (a comparison is recognised from two named cellar wines instead).

## 3. Tests

- Domain: 40 new parser cases (menus in English and Dutch, sixteen texts that must not be read as a menu, the
  eight-course cut), 32 for the checks, the context over long conversations and the comparison.
- `service.test.ts`: 7 new cases. One call with the courses numbered and the schema extended; a made-up wine and a
  course number out of range; one wine for two courses; an empty or broken plan; a follow-up at the end of a
  seven-message conversation; the part off, and a question that is no menu, identical to V1; a comparison; a question
  of fact and no model left as they were.
- `e2e/sommelier-menu.spec.ts` (phone and desktop, features server): a three-course menu with a made-up third wine,
  one call, the follow-up carrying the menu, the kept answer after a reload; Dutch at 360 px with a shared wine;
  a comparison; accessibility; no sideways scroll; and the default server answering a menu as V1 always did.

## 4. What is not proven

- **How well the model plans a menu has not been measured.** The gate asks for a labelled menu set run with the
  model (closeout §6); the set is written, the run needs the owner's budget approval (D-51).
- A plain list without course words is a menu only when the person says so ("menu", "each course", "per gang") or
  writes one course per line. "Oysters, lamb and fondant, what should I open?" is answered as one question.
- Words such as "then" and "dan" can mark courses outside a menu.
- A follow-up finds its menu only within the history the screen sends (about five earlier questions). A later
  question about something else still carries the menu, marked as context only.
- `compareRequest` does not see nicknames, misspellings or grape-only names, and declines when a third wine is
  named or a name fits two wines and no year settles it.
- With `menu` on and `check` off, a course's reason is checked for refs, money and shops only, not for other claims
  about the cellar.
