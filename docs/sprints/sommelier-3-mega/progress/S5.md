## What it does

A person can name friends in a question to their sommelier ("@anna is coming, what do I open?"). The wines that suit
the dish are then ordered for the table: the asker's taste and that of every friend who allows it, pulled toward
whoever would like a wine least. A present for a friend who allows it follows what they like. Nothing else changes:
taste still only orders wines that suit, and never offers one that does not.

## The consent, and why it is its own

Showing a taste profile to friends (on by default since migration 0015) lets friends look at it. Having it weighed
in a friend's sommelier is another use, so it has its own switch, **off for everyone until they turn it on**
(`sommelier_sharing.taste_for_friends`). Both must hold: the friend shares their taste with the asker **and** allows
the sommelier to use it. No existing setting is read as consent, and no default changes for anyone.

## Scope and files

- `supabase/migrations/20261129000051_social_sommelier.sql` — the consent table (own row only) and two functions.
  `sommelier_friend_context(names)` answers per name: `included` (accepted friend, both consents), `no-taste`
  (accepted friend without them), `unavailable` (everyone else: a stranger, a pending request, someone removed,
  the asker, a name that does not exist; never told apart). For `included` it returns closed signals only: the
  kind of wine they said they mostly drink, where they said they like body, tannin, sweetness and acidity, the
  kinds and catalogue regions their own ratings favour (three different wines at least), and how the wines they
  rate highly feel. No wine, producer, note, score, cellar or id.
- `supabase/tests/99_social_sommelier.test.sql` — 45 checks.
- `apps/web/src/server/friends/` — repository, `readSommelierContext` (re-validates every field; fails closed).
- `apps/web/src/app/api/v1/sharing/sommelier/route.ts` — the consent, only with the switch.
- `apps/web/src/server/sommelier/intelligence.ts`, `service.ts`, `conversation.ts` — names are read from the
  question's own text, looked up once per request, used for ordering, never written to the state, never stored.
- Screens: the consent card on the friends page, friend lines in the plan, name suggestions while typing "@".

## Guarantees, and the test that holds each

| Guarantee                                                                                                       | Test                                                                                   |
| --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| A stranger, a pending request, a removed friend, the asker and a name that does not exist read exactly the same | SQL: "not friends", "pending", "ended"                                                 |
| Viewing consent is not sommelier consent; either switch off stops it at the next call                           | SQL: "consent off", "withdrawn", "taste none", "chosen"                                |
| Only closed signals; five keys; no wine, producer, note, score or id                                            | SQL: "nothing else", "no wine…"                                                        |
| A region a household typed itself never leaves the database                                                     | SQL: "only catalogue regions"                                                          |
| What another member of the friend's household rated is not the friend's                                         | SQL: "a member of the friend's household"                                              |
| Fewer than three wines says nothing (no single rating can be read back)                                         | SQL: "below the minimums"                                                              |
| Nothing a screen sends names a friend: only the question's own text                                             | `intelligence-social.test.ts`: "asks the database about exactly the names in the text" |
| A user id or a forged name is only a name the database does not know                                            | same file                                                                              |
| A friend's taste is in no part of the state that travels to the screen                                          | same file                                                                              |
| Withdrawn consent is gone at the next question; nothing is remembered                                           | same file: "when a friend withdraws"                                                   |
| The database cannot answer → nobody is included                                                                 | `friends/service.test.ts`, `intelligence-social.test.ts`                               |
| A question that names a friend is not stored                                                                    | `intelligence-social.test.ts`: "is not kept"                                           |
| No model sees a name: question of fact, earlier turns, engine failure, look-alike names                         | `service-social.test.ts` (10)                                                          |
| Measured as a count of friends, never a name                                                                    | `plan-metrics.test.ts` (S7)                                                            |

## Independent security review

Brief: break it. Verdict: **approve with changes**. "The SQL consent model holds: I found no case where one person's
taste reaches a stranger, and no way around either consent."

| #    | Sev. | Finding                                                                                        | Disposition                                                                                                                                                   |
| ---- | ---- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1-1 | P1   | A question of fact that named a friend skipped the engines and went to the model with the name | **Fixed** (D-21): answered from the counted facts, no model                                                                                                   |
| P1-2 | P1   | An earlier turn that named a friend was sent to the model again as chat history                | **Fixed**: names are taken out of every text sent to a model                                                                                                  |
| P1-3 | P1   | When the engines threw, the question fell back to the model with the name                      | **Fixed**: no answer rather than a model's                                                                                                                    |
| P2-1 | P2   | The function returned the free text of `wines.region`, which a household member can write      | **Fixed** (D-22): catalogue wines only, a pattern, numbers clamped                                                                                            |
| P2-2 | P2   | The consent text left out one signal and promised "nothing is kept" while P1-2 stood           | **Fixed**: the text names the trends and that the friend sees whether it is allowed                                                                           |
| P2-3 | P2   | The function could be called directly, unthrottled                                             | **Fixed**: its own limit inside the function (600 an hour)                                                                                                    |
| P2-4 | P2   | An asker can infer a friend's favoured colour and regions from how the order changes           | **Accepted**: that is what the friend consented to, and less than the taste profile the same person may already view; the consent text says the taste is used |
| P3   | P3   | Name parser edge cases (a 19-character prefix looked up, full-width @, invisible characters)   | **Fixed**. Blocking a person does not exist in the app: recorded, outside this work                                                                           |

## Limitations

- Friends' cellars are not part of this (D-15): "what does @anna have that suits?" is not answered.
- A social answer cannot be rated and is gone after a reload (D-20).
- No browser test (as S3).
- The migration is a draft on a branch: not applied anywhere. It must be numbered after PR #88's 0047 at merge
  time and released by `docs/MIGRATIONS.md` before the switch is named.

## Migration and environment dependencies

Migration `20261129000051_social_sommelier.sql` (additive: one table, two functions). Switch `sommelier_social`
(needs `sommelier_engine`; never by `all`). With the migration missing and the switch on, nobody is included.
