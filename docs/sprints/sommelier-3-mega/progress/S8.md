  miss: behaviour with the switches off, combinations of switches, the client and server boundary, changes
  outside the sommelier's own files, CI and test integrity, fabrication, and whether the documents claim more
  than was done.
- Its findings fixed on the branch each belongs to and merged upward (D-28).
- The documents corrected where they were false or stale.
- `FINAL_REPORT.md`, `RELEASE_PLAN.md` (final), `STATUS.md`.
- A test that pins the Sommelier 3.0 benchmark result (only V1's was pinned).

## Limitations of this validation

- Every review was done by an AI agent. No person has read the code; no person who knows wine has read the
  knowledge or the benchmark's labels.
- The browser tests have not run in CI (it runs them on `main` only).
- Nothing was tried against a real deployment, a real database or a real model.
- The final review did not run the database suite or the browser tests itself (another review was using those
  ports); they were run by the engineering agent, as above.
