## 3. Decisions

1. **No "on" switch in the dashboard.** Clearing a source means a person has read its terms. That stays a deliberate
   `admin_catalog_provider_rights()` call with evidence, outside the UI. A button would make it a click.
2. **"Needs investigation" keeps the link a suggestion.** A suggestion is never shown to people, so nothing changes
   for them; the note and its author are logged. No new state was added to the 004A schema.
3. **One event per used search field, not per request.** Enough to see whether the search is used, where, and
   whether it ends in a choice, without recording a stream of someone's typing.
4. **No recurring import.** Imports stay a manual, audited operator run (`scripts/catalog-tools`). Nothing here
   schedules one.

## 6. Not built, and why

- **Conflict dashboard beyond the queue** (a source's id changing identity, two sources disagreeing): the queue
  shows same-source duplicates and the identity relation; cross-source disagreement has no data yet (no source is
  imported outside the pilot).
- **Sample review of an LWIN import**: no authorised file exists.
- **p50 / p95 latency, cancellations, edit-after-confirm rate** as live metrics: not derivable from per-field events
  (`docs/METRICS.md` says what is and is not measured).
- **Privacy notice update**: nothing in the notice needs to change for features that are switched off; when
  `wine_search` goes on, the notice should mention the anonymous usage counts. Left to the owner's review.
