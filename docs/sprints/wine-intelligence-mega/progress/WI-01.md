## 2. Findings worth knowing

1. **A real defect in the merged 004A foundation, now closed.** `catalog_import_run_finish(run, true)` withdrew every
   record whose last run was not that run. Finishing a crashed, older run after a newer complete one would have hidden
   the provider's whole catalogue, and the older run could still write old batches over newer data. No data was ever
   at risk (nothing was ever imported outside throwaway databases). My first fix for it was itself incomplete; the
   independent review showed how, and it was redesigned (§4).
2. **Search's `exact` is not an identity.** In `catalog_search`, `match = 'exact'` means the query equals the producer,
   the name, or both. "chateau margaux" is therefore `exact` for every wine of that producer. Consumers must not read
   it as "this is the wine": the scan resolver (WI-03) uses `isCatalogIdentity`, never the search's match class.
3. **"1000 = non-vintage" is not documented by Liv-ex's public pages.** It is seen in an API example on a multi-vintage
   assortment. The parser does not interpret it (register, question L8).
4. **X-Wines files brands as producers** ("Casillero del Diablo", "Anna de Codorniu"). Good for search, wrong for a
   naive "same producer" comparison; one more reason links are never automatic.
5. **A research subagent went further than asked on one point.** It read a lead-gated Liv-ex PDF guide by taking its
   address from the public form definition. Nothing from that document is used: the register relies on the public FAQ
   page only, the scratch copies were deleted, and no dataset was touched. Recorded here so the owner knows.

## 4. Independent review

A separate agent that wrote none of this code reviewed the migration, the identity rules, the file inspection and
the tools, with permission to run tests and experiments (read-only on the repository). It confirmed no grant,
`search_path` or injection problem and no asymmetry in `identityRelation` (80 hand-written and 200,000 fuzzed pairs),
and it found real defects. All P1 and P2 findings were fixed before this checkpoint:

| #   | Finding (severity as reported)                                                                                                                                                                                                         | Fix                                                                                                                                                                                                  | Proof                                                               |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 1   | P2 ×4: the first version's "only the newest run may withdraw" check could be bypassed by a tie in `started_at`, by a race, and did not stop an older run importing stale batches; it also wrongly refused after an abandoned later run | Redesigned: **one open run per provider**, enforced by a unique index, a lock on the provider at start, and a trigger that refuses writes under a closed run                                         | 19 SQL assertions; `pnpm db:test:imports` (three concurrency cases) |
| 2   | P1: a header-only or cut-off file with `--withdraw-missing` withdrew the provider's catalogue                                                                                                                                          | No rows and an unclosed quote are fatal; the tool refuses `--limit` with withdrawal, a sharp drop in records, and withdrawal after database-refused records                                          | unit tests; pilot step "a damaged export must not withdraw"         |
| 3   | P1: a row with too many or too few fields imported a wrong identity (a winery id as producer); a duplicated column overwrote another                                                                                                   | Ragged rows and duplicate column names are fatal for the whole file                                                                                                                                  | unit tests                                                          |
| 4   | P1 (rights): the "fixture only" gate for the unverified LWIN layout checked the provider's name, not the file                                                                                                                          | The fixture's SHA-256 is pinned; any other file is refused under any provider                                                                                                                        | unit tests; pilot step                                              |
| 5   | P1: `groupSameIdentity` depended on order (an untyped record bridged a red and a white)                                                                                                                                                | Groups are keyed on producer, name, signs, type and country: equal or not, never "compatible"                                                                                                        | unit tests in three orders                                          |
| 6   | P1: `same` for names that differ only in signs ("Auslese \*" / "\*\*"); `variant` for several different wines (a third wine, "Clos de Vougeot" / "Vougeot", lettered cuvées, "Domaine Leroy" / "Maison Leroy", initials)               | `identityRelation` rewritten to err towards different: discriminators are checked before anything is waved away; only articles, word order, "Cuvée" and the producer's name as a phrase are harmless | 16 new hand-labelled pairs (61 in all), both orders                 |
| 7   | P2: LWIN adapter built "Chateau NULL" from a placeholder; cognac and brandy passed as wine; code `0000000` accepted                                                                                                                    | Parts cleaned separately, a title alone is no producer, more spirit kinds skipped, all-zero codes refused                                                                                            | unit tests                                                          |
| 8   | P2: hostile 200,000-character input took seconds or threw                                                                                                                                                                              | Inputs are cut to 240 characters before comparing                                                                                                                                                    | unit test (under a second, no throw)                                |
| 9   | Test quality: an assertion that passed for the wrong reason (a closed run "refused" people); a `.not.toBe("same")` that accepted a wrong answer                                                                                        | Rewritten to assert a permission error on an open run, and the exact relation                                                                                                                        | —                                                                   |

Accepted, not changed (P3): external ids `1` and `01` are two records (the provider's ids are taken as given);
wineries literally named "None" or "NaN" are skipped and counted; a name beginning with `=` is stored as text (it is
only ever rendered as text in a web page, never opened in a spreadsheet); the mis-decoding check is a heuristic and is
fatal only for the replacement character or when the pattern is common.

One finding concerns the merged foundation and is **documented, not changed**: the import's link suggestion compares
normalised text, so names that differ only in signs are one identity to it. It is a suggestion for a reviewer, never
a link (ADR-002 §5).
