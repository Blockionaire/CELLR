## 4. The four flows, as they are now

**Cellar add (manual).** `app/(app)/cellar/add/page.tsx` → `AddBottleFlow` (`choose → new → details → done`).
`ChooseWine` filters `useWines()` (`GET /api/v1/wines`: **every** wine the household can see, catalogue included) in
memory with `matchesSearch`, 8 shown. "New" → `NewWineForm` → `POST /wines` → `cellar.createWine` →
`pickExistingWine` (own wine first, else exactly one catalogue identity, else a provisional wine). Details →
`POST /bottles` → `cellar.addBottles` (`catalog_vintage` for a catalogue wine's new year). `/api/v1/catalog/search`
has **no caller in the UI**.

**Scan.** `ScanScreen` → client OCR (`features/scan/ocr.ts`) → `POST /scans` → `createScanService.scan`: photo cache
(`recall_confirmed_scan`) → label text (`find_wines_by_label_text` + `recognizeLabelText`, no model) → photo stored →
vision model (budget `scans`) → `normalizeExtraction` → `matchLabel(facts, wines())` where `wines()` is again the whole
visible list. The client re-runs `matchLabel` on its own copy of the list. The person confirms in every mode.

**Koopcheck.** `PurchaseCheckScreen` (`photo → confirm → result`). Photo: `recognize` (text first, else vision; the
photo is prepared in memory and never saved). Manual: an empty form. `compare` → `checkPurchase` (pure code:
ownership, similar wines, taste, verdict). Writes nothing but an `ai_usage` row for a vision call and rate-limit
counters. No wine search; grapes and appellation are typed by hand, so a manual check often ends in `few_details`.

**Insight.** `insights.generate`: household profile (`vintage_insights`) → shared profile
(`shared_wine_profile(vintage, language)`, canonical only, re-checked by `reusableInsight`) → else the paid research
call → `checkInsight` → save → publish when `shareableInsight`. One profile per vintage and language; nothing is reused
across vintages.

Identity shapes and ownership: [`ADR-001`](../ADR-001-identities.md).
