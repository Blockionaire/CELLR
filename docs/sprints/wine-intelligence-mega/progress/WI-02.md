# WI-02 — Wine search in "add a bottle" and Koopcheck · PASS (behind `wine_search`, off by default)

Date: 2026-11-13 · Base: WI-01 checkpoint (`2375fa3`)

## 1. What a person gets (with `wine_search` on)

- **Fles toevoegen:** typing a producer or a wine searches the database as you type: your own wines first, then the
  CELLR catalogue, with typo tolerance and verified aliases. Choose with a tap or with the arrow keys and Enter.
  Nothing found? "… toevoegen als nieuwe wijn" opens the form with what you typed.
- **Koopcheck → "Handmatig zoeken":** the same search. Choosing a wine fills producer, name, colour and origin;
  the vintage stays empty for the bottle in your hand; add the price; compare. "Typ handmatig zonder een resultaat
  te kiezen" is always there. Nothing is added to the cellar.
- **Scan → "Already in your cellar? Search your wines":** the same search, so a wrong reading is corrected by
  finding the wine instead of typing it again.
- **A record of an external source** (only ever one whose rights the owner verified and switched on — today: none)
  is marked "Externe databron, nog niet geverifieerd", opens the form for the person to check, and becomes the
  household's own wine. It never becomes a catalogue wine and nothing about the record is stored.

With the flag off (the default, and production today) every screen is as it was: the picker filters the fetched list
in memory and Koopcheck's typed path is the empty form.

## 3. Findings

1. **Typing before the field works loses the text.** A search field in the server's HTML can be typed into before
   React has attached to it, and React then resets it. The lazily loaded search made that window longer and four of my
   own tests caught it. The search is now rendered client-only: a skeleton stands in until the field can answer, then
   it takes the focus. (The same window exists for every server-rendered input in the app; that is unchanged.)
2. **The phone-profile scan specs are racy in this environment, before this epic.** They choose a photo right after
   `page.goto("/scan")`. On baseline source, with the same setup, 5 of 32 runs failed that way; on this branch 4 of
   139 in one regression run. CI masks it with one retry. No functional defect; recorded as R-26. My new specs wait
   for the screen to be interactive first.
3. **The typed path of Koopcheck used to end in "weinig gegevens" most of the time**, because colour and origin had to
   be typed. Choosing from the search fills them, so the comparison has something to compare with. (Grapes and
   appellation come with WI-04.)

## 6. Not done, on purpose

- The wishlist's "add a wish" form still types a wine by hand. Same component would fit; left for a follow-up to keep
  this change reviewable.
- "Recently added" (nothing typed) and the fallback list still come from `GET /api/v1/wines`, which returns every
  wine the household can see. A bounded "recent wines" endpoint is the follow-up that removes the last reason to
  fetch that list (R-23).
